# RL_FJSP 后续任务与研究计划

更新日期：2026-10-03。负责人：项目作者；工程实现与检查可由编码助手协助。

本计划连接两件事：把现有项目维护成可复现的研究仓库，以及验证一个值得继续投入的研究问题。
八周是第一轮验证的建议时间窗，不是发表承诺。阶段未通过验收时顺延，先定位原因再扩大训练。

## 1. 本轮目标与范围

工程目标：外部使用者能安装、运行小实验、验证调度，并从结果追溯到代码版本与配置。

研究候选问题：机器故障发生后，在相同在线计算预算下，学习选择修复区域，能否改善局部重调度的完工时间与计划稳定性权衡？

这是待验证假设。动态 FJSP、学习控制搜索、合法解码本身都不能直接认定为新贡献。
先验证显式区域选择的增量价值，再决定是否增加算子选择与预算分配。

第一版范围：静态实例生成初始计划；一次有限时长机器故障；故障发生在当时空闲的机器上；
已完成与正在加工的工序冻结；只修复尚未开始的工序。首轮不同时加入插单、加工延迟和连续故障。
这一范围的结论仅适用于对应故障模型，不能外推到加工中断、抢占或一般工业系统。

- [ ] R11 / P1：定义局部区域外工序的处理：默认保留；有依赖冲突时按预设规则扩展区域并记录扩展量。

## 8. 第五至六周：只验证一个学习机制

候选区域先用简单、可解释的规则生成：故障机器后续块、受影响工序依赖闭包、关键路径块、固定规模邻域。
第一版学习动作只选区域；修复算子和预算固定。区域大小也应受控，否则增益可能仅来自更大搜索范围。

- [ ] R19 / P1：在相同状态上试跑各候选区域，记录收益、偏移、实际耗时与评估次数。
- [ ] R20 / P1：建立“事后最佳区域”诊断；它需要额外计算，只用于分析，不作为可部署基线。
- [ ] R21 / P1：判断固定区域与事后最佳区域之间是否有足够差距；几乎无差距时停止训练区域选择器。
- [ ] R22 / P1：采集监督样本，标签来自同预算候选试跑；采样与标签计算成本单独报告。
- [ ] R23 / P1：先训练小型排序器/分类器，对比随机选择和简单自适应选择。
- [ ] R24 / P1：监督模型有稳定收益后，再判断是否需要多步 RL；保留监督模型作为消融。
- [ ] R25 / P1：若采用 RL，奖励和最终指标一致，并归一化规模；在验证集确定权重，测试集不得调参。

阶段门槛：在多个验证场景与种子上观察到同预算改进，而不是只在 MK01 的单次运行上更好。
三种子仅用于早期排查和信号判断，不作为最终统计结论。没有信号时先核对标签、区域覆盖、状态信息与成本。

## 9. 第七周：实验与消融

训练、验证与测试必须按基础实例划分。仅改变同一实例的扰动种子不能证明跨实例泛化。
Brandimarte 15 个实例用于外部评估；训练样本可来自有公开规则的合成实例，记录生成器与种子。
若必须在部分 Brandimarte 上调参，明确列出并从最终未见实例评价中排除。

- [ ] R26 / P1：冻结测试划分、故障分布、事件前计划来源、质量指标和计算预算。
- [ ] R27 / P1：覆盖早/中/晚事件时刻与轻/中/重故障时长；分组规则在看测试结果前确定。
- [ ] R28 / P1：先在 toy、MK01 和一个中等规模实例上测量性能，再确定全量预算。
- [ ] R29 / P1：正式学习实验至少五个训练种子；每个实例含多个独立事件，所有方法配对比较。
- [ ] R30 / P1：报告分实例结果、均值、标准差、配对差值及置信区间；最佳值作为补充。
- [ ] R31 / P1：将同一基础实例上的事件视为相关样本，避免把大量事件当成独立实例制造显著性。
- [ ] R32 / P1：消融学习选择、动态状态特征、区域扩展、稳定性项与 RL 微调，保持其余条件一致。
- [ ] R33 / P1：绘制质量与时间、质量与稳定性的权衡曲线，以及合法率、兜底率和失败案例。

指标定义：

| 指标 | 约定 |
| --- | --- |
| 质量 | 事件后 makespan；另报告 `C_new - event_time` 的剩余完工时间 |
| 稳定性 | 原计划中未启动工序的平均绝对开始时间偏移，除以预先定义的时间尺度 |
| 分配变化 | 同一工序集合上的机器改变比例 |
| 代价 | 完整在线耗时、评估次数、离线训练及标签采集成本 |
| 正确性 | 动态合法率、冻结约束违规数、兜底率、超时率 |

故障本身会增加完工时间，所以相对事件前计划的恶化只作描述。
算法优劣主要对比同一事件下的可行基线。稳定性与质量单独报告；若使用加权目标，报告权重敏感性。

- [ ] R38 / P1：撰写问题定义、方法、实验、局限；证据充分后再确定投稿定位。

值得继续的证据：在留出实例与配对扰动上，同预算优于强规则/自适应基线，
改进能归因于区域决策，且没有用明显更差的稳定性换取未披露的质量增益。
单个实例更好、模型更大、增加扰动类型、调度合法，均不能单独证明机制创新。

若规则方法同样好，保留负结果并研究何时无需学习；若区域选择价值不明显，暂停这条机制。
若动态模型工程成本过高，回到静态改进环境，验证学习邻域排序相对等预算规则搜索的价值。
任何转向都先更新研究假设和比较协议，再运行新的大实验。
